01
Drone command-link detection

MAVLink NIDS demo

Replay a recorded capture through Suricata and compare the stock rule set with my own MAVLink rules. On the bundled test captures the stock rules stay silent and the custom rules catch the flood, command injection and spoofed-position traffic.

  • Understands how attacks on a drone command link look on the wire
  • Writes detection rules from the protocol, not from a template
  • Offline replay only: it sends no attack traffic

Honeypot network

Low-interaction SSH, Telnet, HTTP and banner sensors that pretend to be vulnerable, record what attackers try and ship HMAC-signed events to a collector. The collector analyses brute force, credential lists, campaigns and exploit attempts by CVE.

Malware analysis

Malware lab

Static analysis, then detonation in a no-network, read-only, capability-dropped Docker sandbox watched with strace. It extracts indicators, maps behaviour to MITRE ATT&CK, writes a YARA rule and a report. It ships with safe training specimens, not live malware.

  • Ransomware, persistence and C2 behaviour, recognised and written up
  • Careful containment by design
  • Reports in Markdown, HTML, JSON and STIX 2.1

Industrial control systems

ICS attack simulator

A simulated water treatment plant with a PLC, an independent safety system and Modbus/TCP. Eight attack scenarios mapped to ATT&CK for ICS run against seven switchable mitigations, and a consequence model scores every run.

  • Shows what an attacker changes in a process, and what that costs
  • Measures which mitigations actually help
  • Attacks only ever touch the simulator

03

The research

My final-year project. It is a purple-team study, so it needs both sides.

In progress · due April 2027

Skyguard Purple Lab

Testing Suricata detection of attacks on drone command links. A simulated lab with an ArduPilot drone, a ground station, attacker and relay hosts and a Suricata sensor on an isolated network, with ground-truth logging so every alert can be scored.

  • RQ1How well do default Suricata rules detect flooding, command injection and spoofed position messages, and how fast?
  • RQ2Do custom MAVLink rules improve detection, and by how much?
  • RQ3What is the false-alarm rate of each rule set on normal mission traffic?
  • RQ4Do published results on recorded relay captures (Shadow-GCS dataset) hold in live traffic?

The lab and scoring tools are built and tested. Ethics approval comes before any attack work, and thresholds are fixed before any test run. There are no results yet and I will not claim any until the experiments are done. The public demo of the custom rules is here.

04

The hunt

A hunting bat changes its call as it closes in. This is a spectrogram drawn from that pattern: slow, long calls while searching, faster ones on approach, then the terminal buzz. It is also how I run an engagement.

Search
Recon and scoping

Read the scope and rules of engagement. Passive first, then active. Map what exists before touching any of it.

Approach
Enumeration and analysis

Calls get faster and more specific. Services, versions, users, paths. Work out what is actually exploitable and why.

Terminal buzz
Action and report

Short and precise, only inside scope. Then write it up so someone else can reproduce it and fix it.

Rules I work by

  1. Scope and authorisation come first. No scope, no test.
  2. I only test what I own or have written permission to test. My lab, Hack The Box, CTFs.
  3. I write down what I did, in an order someone else can follow.
  4. A finding without a fix is half a report.
